# Note-writing guide

This guide covers how the team writes and files working notes in `docs/`.

## File names

Name each note after its topic in lower case, with hyphens between words.

## Structure

Start each note with a one-line summary. Group related points under a heading, and keep one topic
per heading.

## Quoting

When you quote a message from a chat thread, put it in a blockquote and name the channel it came
from. Write “ship it” in a note only when the release owner has approved the release.

## Dates and ranges

Write dates as YYYY-MM-DD. For a span of weeks, give the first and last week numbers, such as
weeks 10–12.

## Open items

List what is still open at the end of a note, rather than ending on a trailing thought…

## Terms

Some notes use Japanese terms from the partner team. For example, 漢字 (kanji) means the
Chinese characters used in written Japanese. Write such a term in its original script the first
time, followed by its reading in parentheses.

## Markdown syntax

Notes follow CommonMark. For the details of emphasis and link syntax, see the
[CommonMark specification](https://spec.commonmark.org/0.31.2/).
